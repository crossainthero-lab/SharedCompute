# Test evidence: what ran on real hardware, and what did not

Last updated 2026-10-12 for v0.3 (branch `feature/mvp-integration`). The only hardware available was one
**Intel MacBook Pro**: Core i7-9750H, Intel UHD Graphics 630 + AMD Radeon Pro 5300M, macOS 26.6, no NVIDIA GPU.
No second network was available. Nothing below claims otherwise.

## Manual runs on the Mac (2026-10-12)

1. `python -m sharedcompute_agent diagnose`: reported the two Mac GPUs as non-CUDA, the CPU as able to run
   `agent.hashchain`, and nothing offered without flags.
2. `diagnose --gpu 1 --offer-cpu --selftest`: AMD GPU refused, CPU offered, GPU self-test skipped with the reason.
3. v0.3 server started on the v0.2 database: migration 0002 applied; old agent devices marked for re-offer.
4. `run --offer-cpu --gpu 1` with the existing node token: registered, offered only the CPU, logged why the
   AMD GPU was refused, ran a CPU pipeline-check job. The UI showed **CPU · VERIFIED** with server-measured billing.
5. A CUDA matmul job with "min compute capability 5.0" queued, with the quote explaining that no connected
   provider offers a compatible GPU.

## What the first NVIDIA test must establish

See [HARDWARE_TESTING.md](HARDWARE_TESTING.md). In order of risk:

1. The driver JIT-compiles the committed PTX (`diagnose --gpu 0 --selftest` passes).
2. nvidia-smi / NVML parsing matches the real output on that driver version.
3. The CUDA probe matches GPUs by PCI bus id.
4. The display-GPU guard reads `display_active` correctly.
5. An end-to-end GPU job reaches **GPU · VERIFIED RESULT**, with sensible kernel timing.
6. The same over a second network (Tailscale or VPS).
